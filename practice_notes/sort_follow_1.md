# 정렬 알고리즘 구현 따라가기 1

## 1. Bubble Sort

- **소개:** 이웃한 두 값을 비교하고 왼쪽 값이 더 크면 서로 바꾼다. 한 번의 반복이 끝나면 남은 값 중 가장 큰 값이 오른쪽 끝에 놓인다.
- **구현에 대해 느낀 점:** 비교만 추가된 단계에서는 배열의 순서가 그대로였고, 조건에 따른 교환이 들어가면서 실제로 값이 이동했다. 오른쪽에 확정된 구간이 늘어나는 모습을 보니, 다음 반복에서 비교 범위를 줄이는 이유를 이해할 수 있었다.
- **개선 버전의 의의:** 마지막 교환 위치를 기록하면 그 뒤쪽은 다음 비교에서 제외할 수 있다. 교환이 한 번도 없으면 바로 종료하므로, 이미 정렬된 배열을 끝까지 반복해서 확인하지 않는다.
- **캡처:** `정렬과제_01_Bubble_Sort.png` — 99가 오른쪽 끝에 확정된 뒤, 두 번째 반복에서 17과 8을 비교하는 장면.

## 2. Selection Sort

- **소개:** 아직 정렬하지 않은 구간을 끝까지 살펴 가장 작은 값을 찾고, 그 구간의 맨 앞으로 옮긴다. 이 과정을 반복하면 왼쪽부터 값이 하나씩 확정된다.
- **구현에 대해 느낀 점:** 최솟값 후보를 바꾸는 것과 배열의 값을 교환하는 것은 서로 다른 작업이었다. 한 자리만 처리하던 코드가 두 자리, 전체 자리로 확장되는 과정을 보며 바깥 반복문의 역할이 분명해졌다.
- **개선 버전의 의의:** 성능 측정용 구현에서는 최솟값을 변수에 보관해 비교할 때마다 같은 배열 위치를 다시 읽는 작업을 줄였다. 다만 남은 구간 전체를 확인하는 과정은 그대로이므로 비교 횟수 자체가 줄어드는 개선은 아니다.
- **캡처:** `정렬과제_02_Selection_Sort.png` — 첫 값 4가 확정되고, 다음 최솟값 후보 8과 23을 비교하는 장면.

## 3. Insertion Sort

- **소개:** 왼쪽에 정렬된 구간을 유지하면서 다음 값을 알맞은 위치에 끼워 넣는다. 삽입할 값보다 큰 값들을 오른쪽으로 밀어 빈자리를 만든다.
- **구현에 대해 느낀 점:** 처음에는 값을 계속 교환하며 왼쪽으로 이동시켰지만, 나중에는 삽입할 값을 따로 보관하고 큰 값만 밀도록 바뀌었다. 화면에 따로 빼 둔 값과 빈자리가 표시되어, 이동 중 같은 값이 두 칸에 보여도 원래 값이 사라진 것은 아니라는 점을 이해했다.
- **개선 버전의 의의:** 자신보다 작거나 같은 값을 만나면 그보다 왼쪽은 더 비교하지 않아도 된다. 또한 매번 두 값을 교환하는 대신 큰 값만 한 칸씩 옮기고 후보를 마지막에 한 번 넣으면 배열에 값을 쓰는 작업을 줄일 수 있다.
- **캡처:** `정렬과제_03_Insertion_Sort.png` — 23을 따로 보관하고 99를 오른쪽으로 밀어 삽입 위치를 만드는 장면.

## 4. Shell Sort

- **소개:** 일정한 간격인 gap만큼 떨어진 값들끼리 삽입 정렬한 뒤, 간격을 점점 줄인다. 마지막에는 gap을 1로 만들어 전체 배열을 정렬한다.
- **구현에 대해 느낀 점:** gap 3에서 일부 부분 배열만 정렬한 단계와 모든 부분 배열을 처리한 단계가 구분되어 있었다. 부분 배열이 정렬되어도 전체 순서는 아직 맞지 않았고, gap 1을 적용해야 정렬이 완성된다는 점이 인상적이었다.
- **개선 버전의 의의:** 큰 간격으로 값을 먼저 이동시키면 마지막 삽입 정렬에서 한 칸씩 멀리 이동해야 하는 부담을 줄일 수 있다. 부분 배열별 반복을 전체 원소 순회로 바꾼 코드는 같은 정렬 작업을 더 단순한 반복 구조로 표현한 것이며, 반복문 수가 줄었다고 비교 횟수도 반드시 줄어드는 것은 아니다.
- **캡처:** `정렬과제_04_Shell_Sort.png` — gap 3의 부분 배열에서 4를 보관하고, 인덱스 2의 8을 인덱스 5로 이동하는 장면.

## 5. Heap Sort

- **소개:** 부모가 자식보다 크거나 같은 최대 힙을 만들면 루트에서 가장 큰 값을 찾을 수 있다. 이 값을 배열 뒤로 옮기고, 힙 크기를 줄여 다시 최대 힙을 만드는 과정을 반복한다.
- **구현에 대해 느낀 점:** 배열 인덱스가 트리의 부모와 자식에 대응하는 점과, 마지막 부모부터 위로 올라가며 힙을 만드는 이유가 처음에는 헷갈렸다. 루트의 최대값을 빼낸 뒤에는 새 루트 때문에 깨진 조건을 아래 방향으로 복구해야 한다는 흐름을 확인했다.
- **개선 버전의 의의:** 개선된 downheap은 재귀 대신 반복문을 사용해 재귀 호출 부담을 없앤다. 루트 값을 따로 보관하고 큰 자식을 위로 올린 뒤 마지막 빈자리에 루트 값을 넣으므로, 내려가는 매 단계에서 두 값을 교환하는 작업도 줄인다.
- **캡처:** `정렬과제_05_Heap_Sort.png` — 최대값을 뒤로 보낸 뒤, 줄어든 힙에서 자식 값을 비교하며 힙을 복구하는 장면.

## 6. Count Sort

- **소개:** 각 값이 몇 번 나왔는지 센 다음, 누적합으로 결과 배열에서 들어갈 위치를 계산한다. 원소끼리 대소를 비교하는 대신 값의 개수와 위치 정보를 이용한다.
- **구현에 대해 느낀 점:** counts가 처음에는 등장 횟수였지만 누적합을 계산한 뒤에는 배치 위치를 나타낸다는 점이 핵심이었다. 뒤에서부터 원소를 읽고 counts를 하나 줄여 배치해야 같은 값들의 원래 순서를 유지할 수 있다는 점도 이해했다.
- **캡처:** `정렬과제_06_Count_Sort.png` — 누적합을 이용해 원본 배열의 값을 결과 배열의 해당 위치에 넣는 장면.

## 7. Radix Sort: LSD

- **소개:** 일의 자리부터 십의 자리, 백의 자리 순서로 각 자릿수를 기준으로 정렬한다. 같은 자릿수끼리는 이전 순서를 유지해야 앞 단계에서 만들어진 낮은 자릿수의 순서가 보존된다.
- **구현에 대해 느낀 점:** 일의 자리 정렬만 끝난 화면은 숫자 전체의 크기순과 달랐다. 십의 자리 정렬을 거쳐 마지막 자릿수까지 처리해야 전체 순서가 맞았고, 계수 정렬의 안정성이 다음 단계로 이어지는 데 꼭 필요하다는 점을 알게 됐다.
- **캡처:** `정렬과제_07_Radix_LSD.png` — 일의 자리 정렬 이후 십의 자리 digit을 이용해 결과 배열에 값을 배치하는 장면.

## 8. Radix Sort: MSD

- **소개:** 문자열의 첫 글자부터 같은 글자끼리 묶고, 각 묶음 안에서 다음 글자를 기준으로 다시 정렬한다. 글자가 다른 묶음 사이의 순서는 이미 결정되어 있으므로 같은 접두사를 가진 구간만 재귀적으로 처리한다.
- **구현에 대해 느낀 점:** 처음에는 첫 글자 분류와 특정 구간의 둘째 글자 처리가 따로 작성되어 있었고, 이후 공통 함수와 재귀로 일반화됐다. 시각화의 depth와 스택을 보니 어느 구간을 어떤 글자로 분류하는지 이해하기 쉬웠다. 단어가 끝난 경우는 end 버킷으로 구분해 더 내려가지 않는 점도 중요했다.
- **개선 버전의 의의:** 임시 배열을 재귀마다 새로 만드는 대신 한 번 만든 배열을 공유해 반복적인 배열 할당을 줄였다. 이 개선은 재귀 호출 자체를 없애는 것이 아니라 작업 공간을 재사용하는 것이다. 별도 e~o 버전은 입력 문자의 범위를 제한해 버킷 수를 27개에서 12개로 줄이며, 그 범위를 벗어난 문자가 없는지 검증한다.
- **캡처:** `정렬과제_08_Radix_MSD.png` — 시각화 버전 `ch6_8_radix_msd.py`에서 같은 첫 글자 구간을 depth 1에서 분류해 임시 배열에 배치하는 장면.
